# 파일 삭제·PDF 및 이미지 편집

## General — 방향과 범위

2026-09-20 변경 결정: 버전 관리 UI를 없애고 같은 파일의 현재 편집을 저장한다.
최초 원본과 이미 존재하는 과거 이력은 보존하되, 새 저장마다 이력을 계속 추가하지 않는다.
PDF의 원문과 필기 데이터를 분리해 저장하므로 다시 열어도 추가한 필기를 지울 수 있다. PNG는 기존처럼 필기가 픽셀에 합쳐진다.

## Function — 사용자 흐름

- 파일 목록에서 여러 파일을 체크하고 **선택 삭제** → 확인 → 휴지통으로 이동한다.
- 폴더 메뉴의 **삭제**는 활성 파일과 하위 폴더가 없는 폴더에 적용된다.
- PDF/이미지 미리보기의 **새 탭에서 편집**으로 `/files/{id}/edit`를 연다.
- PDF: 페이지를 세로로 연속 스크롤하며 읽는다. 탭의 전체 영역을 사용한다.
- 기본 자동 맞춤은 마우스 중심 PC에서 페이지 전체가 화면 높이와 너비 안에 들어오게 하고, 터치 기기에서는 기존 폭 맞춤을 유지한다.
- 메뉴의 화면 맞춤·배율에서 자동/페이지 맞춤/폭 맞춤 및 폭 기준 25~200% 배율을 선택한다. 페이지 맞춤은 페이지별 회전·비율과 창 크기 변경에 대응한다.
- 최초 진입은 읽기 모드이며 햄버거와 오른쪽 상단 펜·형광펜·지우개·읽기·되돌리기·다시 실행 아이콘 버튼을 표시한다. 저장·배율·페이지 이동·편집 도구·필기 목록은 메뉴에 모은다.
- 펜·형광펜·한글 텍스트·부분 지우개를 선택하면 메뉴를 닫고 문서에서 사용한다. 텍스트는 입력 후 배치한다.
- 상단 도구 버튼은 읽기 모드에서도 표시하며 현재 도구를 강조한다. 메뉴에서도 도구를 선택할 수 있다.
- 펜·형광펜·지우개·텍스트 수정·필기 삭제를 실제 작업 순서대로 최대 100회 되돌린다. 실행취소·다시 실행 시 현재 스크롤 위치를 유지한다.
- `Ctrl/Cmd+Z`는 되돌리기, `Ctrl/Cmd+Shift+Z` 또는 `Ctrl+Y`는 다시 실행이다. 텍스트 입력 중에는 입력란 자체의 되돌리기를 유지한다.
- 되돌린 뒤 새 작업을 하면 다시 실행 기록을 비운다. 기록은 현재 편집 탭에서만 유지된다. 이미지 회전·크기 변경·자르기·초기화도 필기와 함께 순서대로 되돌린다.
- 읽기 모드에서는 손가락으로 스크롤·확대한다. 필기 중 상단의 읽기 전환 버튼으로 스크롤 모드로 돌아간다.
- 메뉴의 전체 화면 전환은 지원 브라우저에서 브라우저 전체 화면을 사용한다. 일반 상태에서도 문서는 탭의 전체 영역을 채운다.
- 이미지: 펜·형광펜·텍스트, 드래그로 자르기, 90도 회전, 가로·세로 크기 변경.
- **저장** → 같은 파일의 현재 편집 갱신. 버전 이력·복원 UI는 제공하지 않는다.
- 저장 실패 시 현재 편집을 유지하고 오류를 표시한다. 미저장 상태에서 나가면 경고한다.

## Spec — 저장·삭제 규칙

### PDF

- PDF.js로 페이지를 그리고 pdf-lib로 원문 페이지 위에 필기 이미지를 합성한다.
- 페이지별 비율과 위치를 유지하면서 화면 근처 페이지만 렌더링한다. 멀어진 페이지의 캔버스는 해제하고 다시 보이면 원문과 필기를 복원한다.
- 지우개는 필기 레이어에만 적용한다. 원문 글자·그림은 지우지 않는다. 지우기 작업도 저장·복원하며 되돌리기·다시 실행을 지원한다.
- 기존 PDF 텍스트·페이지를 유지한다. 기존 본문의 글자 자체를 고치는 편집은 제공하지 않는다.
- PDF 내부 첨부 파일 `devvault-original-v1.pdf`와 `devvault-marks-v1.json`에
  편집 시작 원문과 정규화된 필기 좌표를 저장한다.
- 다시 열 때 내장 원문과 필기를 분리하여 복원한다. 이전 편집본을 반복해서 중첩하지 않는다.
- 다른 PDF 뷰어에서도 필기 결과가 보이지만 필기 목록 재편집은 DevVault 기능이다.
- 원문 첨부 때문에 편집본의 저장 용량은 증가하며 기존 저장소 용량 제한에 포함된다.
- 최대 입력·출력 50MiB. 최대 필기 10,000개, 전체 좌표 200,000개.
- 암호 입력은 지원하지 않는다. 암호화·손상 등 처리 불가능한 문서는 오류를 표시한다.
- 페이지 회전 0/90/180/270 및 CropBox 위치를 고려하여 필기를 저장한다.

### 이미지

- 입력 PNG/JPEG/WebP/GIF/BMP, 출력 PNG. 최대 1,600만 화소, 한 변 16,000px.
- 저장·자르기·회전·크기 적용 시 현재 필기와 텍스트가 픽셀에 합쳐진다.
  현재 탭에서는 변환을 되돌리면 변환 전 이미지와 개별 필기가 복구된다. 저장한 PNG를 다시 열면 합쳐진 필기는 개별 복구되지 않는다.
- GIF는 애니메이션을 보존하지 않는다. 이미지 메타데이터는 Canvas 출력에 보존하지 않는다.

### 기기 임시 저장·복구

- 파일 접근 권한 확인과 원본 로딩 후 파일 ID·체크섬·서버 버전에 해당하는 IndexedDB 임시 편집을 조회한다.
- 필기 완료·이미지 변환·되돌리기 후 500ms 동안 추가 변경이 없으면 현재 필기와 변환 이미지를 저장한다. 연속 필기 중에는 저장을 묶어 입력을 우선한다. 서버 업로드는 하지 않는다.
- 다시 열면 복구/버리기를 선택한다. 복구 전 편집과 서버 저장을 막으며 복구 실패 시 데이터를 유지한다.
- 저장 성공 또는 저장 기준으로 되돌리면 임시 편집을 삭제한다. 저장 공간 부족·브라우저 저장 차단은 안내한다.
- 기기 임시 저장은 브라우저 데이터 삭제 시 사라지며 완료되기 전 종료된 작업은 보장하지 않는다. 이전 되돌리기 기록은 복구하지 않는다.
- 같은 파일을 여러 탭에서 편집하면 마지막으로 기록된 임시 편집이 남는다. 서버 원본은 변경하지 않는다.

### 펜 전용 모드

- 펜 전용 모드는 브라우저가 `pen`으로 전달하는 입력만 필기한다. 편집 중에는 문서와 여백의 기본 스크롤·핀치 확대·길게 누르기 메뉴를 차단한다. 스크롤·확대는 읽기 버튼으로 전환한다.
- 펜이 `touch`로 전달되는 기기에서는 손과 구분할 수 없어 펜 전용 모드에서 필기되지 않는다. 실제 iPad/808펜 입력과 OS 메뉴는 기기에서 별도 확인한다.
- 입력 종류에 따라 접촉 도중 터치 동작을 변경하지 않는다. 마우스 편집은 펜 전용 모드를 끄고 사용한다.
- 손바닥 거부와 펜 호버 없는 기기의 제스처 처리는 OS·브라우저에 따라 실제 기기 확인이 필요하다.

### 필기 입력·렌더링

- 펜 이동 시 기존 획을 다시 순회하지 않는다. 현재 획의 새 구간만 버퍼에 그리고 화면 프레임마다 원래 필기 위에 합성한다.
- 형광펜 투명도는 전체 획에 한 번 적용하고, 지우개는 필기 레이어에만 적용한다. 펜을 뗄 때 마지막 좌표까지 반영한다.
- 변경 없는 페이지와 이미 화면에 반영한 완료 획은 반복 렌더링하지 않는다. 전체 데이터 JSON 검증은 파일 읽기·저장 경계에 유지한다.
- 필기 영역의 텍스트 선택·길게 누르기 메뉴·드래그를 막는다. 다른 손가락의 취소 이벤트가 진행 중인 펜 획을 취소하지 않도록 포인터 ID를 확인한다.

### 공통 저장

- `POST /api/files/{id}/content`: multipart `file`, `expectedVersion`. 같은 파일 ID에 현재 편집을 저장한다.
- PDF→PDF, 이미지→PNG만 허용하고 입력·출력 50MiB, 형식 시그니처·소유권·용량을 검사한다.
- 첫 저장에서는 원본을 보존한다. 이후에는 현재 파일을 교체하고 DB 커밋 후 대체된 물리 파일을 삭제한다. 기존 과거 이력은 삭제하지 않는다.
- 충돌 방지용 내부 번호는 유지한다. 두 탭에서 변경한 경우 늦은 저장은 409이며 현재 필기와 임시 저장을 유지한다.
- 사용량은 원본·기존 이력·현재 파일의 합이다. 현재 파일 교체 시 그 크기를 차감해 필요한 추가 용량을 계산한다.
- 실패·DB 롤백 시 새 바이트만 정리하고 이전 바이트를 유지한다. 파일 ID·폴더·태그·즐겨찾기는 유지한다.
- 이전 클라이언트용 versions API와 기존 스키마는 호환성을 위해 유지하지만 현재 편집 UI에서는 호출하지 않는다. 이번 변경에 추가 DB 마이그레이션은 없다.

### 삭제

- `POST /api/files/bulk-delete`: `{ "fileIds": [1, 2] }`, 성공 `204`.
- ID는 양의 정수 1~100개, null 금지. 중복 ID는 한 번만 처리한다.
- 모든 파일의 소유권과 활성 상태를 먼저 검사한다. 하나라도 유효하지 않으면 변경하지 않는다.
- 인증 없음 `401`, 잘못된 요청 `400`, 다른 사용자의 파일·없는 파일·휴지통 파일 `404`.
- 폴더 삭제 시 활성 파일/하위 폴더가 있으면 `409`.
- 휴지통 파일만 남은 폴더는 파일의 폴더 연결을 해제한 뒤 삭제한다.
  해당 파일 복원 시 최상위 폴더로 복원한다.

## 검증

- 백엔드 `FileStorageServiceTest`, `FolderServiceTest`, `FileManagementIntegrationTest`:
  소유권·요청 검증·일괄 삭제의 부분 변경 방지·폴더 삭제 후 복원. 통합 테스트는 격리된 테스트 DB/임시 저장소 사용.
- 프론트 `npm run test:editing`: PDF 원문 바이트·텍스트·첨부 필기 보존 및 회전/CropBox 렌더링 확인.
- `npm run test:editor-browser`: 3107 포트의 로컬 프론트에서 API를 가로채는 브라우저 검사.
  태블릿 화면 채움·도구 숨김·연속 20페이지·손가락 스크롤·화면 밖 캔버스 해제와 필기 복원·부분 지우기와 취소·저장 후 재편집·전체 화면·가로/세로·확대를 검증한다.
  추가로 펜/형광펜/지우개 되돌리기·다시 실행·새 작업 후 다시 실행 초기화·페이지 간 취소·단축키·저장 기준 복원과 PC 자동 페이지 맞춤·폭 맞춤·수동 배율·창 크기 변경을 검증한다.
  임시 PDF/변환 이미지 새로고침 복구·버리기, 이미지 변환 되돌리기/다시 실행, 펜 전용 모드의 손가락 필기 차단과 펜 입력도 검사한다.
  Playwright는 환경에 제공해야 하며 `DEVVAULT_PLAYWRIGHT_MODULE`로 모듈 경로,
  `DEVVAULT_BROWSER_CHANNEL`로 브라우저 채널을 지정할 수 있다(기본 Chrome).
- `FileVersionIntegrationTest`: 같은 ID 저장, 원본/이력 보존, 복원, 동시 저장 409, 권한·형식·용량 거부, 영구 삭제를 격리 H2/임시 파일로 검증한다.
- 운영 DB·운영 배포·실제 태블릿 펜 입력은 별도 검증 대상이다.

- `DEVVAULT_PEN_REPRO=1 node scripts/check-editor-browser.cjs`: 30개 획 이후 이동당 선 처리량, 실행취소 스크롤 유지, 선택 방지, 다른 포인터 취소에 대한 회귀 검사.
- 자동 입력 검사는 실제 태블릿의 필기 지연·펜 펌웨어·OS 손바닥 거부 검증을 대신하지 않는다.
